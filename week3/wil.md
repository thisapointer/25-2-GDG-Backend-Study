## 1. Repository Layer(DAO + DB)
데이터베이스에 접근하여 **CRUD** 작업을 실행  

> * Create: 데이터 생성  
> * Read: 데이터 조회  
> * Update: 기존 데이터 수정  
> * Delete: 데이터 삭제  

### Annotation
---
> `@repository`  
> \- 레포지토리 명시

### 데이터베이스에 접근하는 방법
-> **애플리케이션 서버**가 <u>SQL</u>을 **DB**에 전달  
-> **DB**는 전달된 SQL을 실행하고 결과를 응답

### * JDBC
    Java에서 데이터베이스에 접근하기 위한 표준화된 API  

### * ORM(Object-Relational Mapping)
    객체와 관계형 데이터베이스의 데이터를 자동으로 매핑해주는 것  
    - 이것으로 둘 사이의 패러다임 불일치를 해결함  

<br>

## 2. JPA(Java Persistence API)
    Java의 ORM 기술 표준  
    Java에서 객체를 데이터베이스에 저장하고 관리하기 위한 인터페이스와 기능을 제공하는 API  
    ex) Hibernate

<br>

---
### EntityManager
    엔티티 객체를 데이터베이스와 연결해주는 창구 역할  
    - SQL을 직접 작성하지 않고도 CRUD 작업 수행 가능  
    - 엔티티 매니저는 엔티티를 영속성 컨텍스트에 저장

#### Annotation
> `@PersistenceContext`  
> \- 엔티티 매니저 명시

#### 메소드
> `.find(객체 클래스, 기본키)`  
> \- 데이터 조회, 객체 리턴  
> `.createQuery(SQL문 문자열, 객체 클래스)`  
> \- JPQL 쿼리를 실행하기 위한 쿼리 객체 생성  
> `.getResultList()`  
> \- [쿼리 객체 메소드] List 객체로 반환  
> `.setParameter("바꿀 SQL문 문자열(:___)", 넣을 값)`  
> \- [쿼리 객체 메소드] SQL문의 부분을 넣고자 하는 값으로 치환  
> `.persist(객체)`  
> \- 영속성 컨텍스트에 등록  
> `.remove(객체)`  
> \- 영속성 컨텍스트에서 제거  

### * JPQL
    SQL과 비슷하지만, 테이블이 아니라 엔티티 객체를 기준으로 쿼리 작성

### 영속성 컨텍스트
    JPA에서 엔티티를 관리하기 위해서 만들어져있는 가상 공간  
    - 엔티티 매니저를 통해서 영속성 컨텍스트에 접근  
* 엔티티 생명 주기  
    + 비영속: 영속성 컨텍스트와 관련 없는 상태
    + 영속: 영속성 컨텍스트에 저장 / 관리됨
    + 준영속: 저장되었다가 분리된 상태
    + 삭제: 영속성 컨텍스트에 엔티티가 삭제될 거라고 기록한 상태
* 영속성 컨텍스트의 특징
    + **1차 캐시**
    + **동일성 보장**
    + <u>트랜잭션</u>을 지원하는 **쓰기 지연**
        - 커밋 시점에 한 번에 묶어서 DB에 보냄
        - 네트워킹 횟수가 줄어 효율적
    + **변경 감지(Dirty Checking)**

### *트랜잭션
> 데이터베이스에서 수행되는 작업의 단위  
> ex) 상품 결제(주문 정보 저장, 상품 재고 차감, 회원 포인트 적립)  
> - 여러 개의 데이터베이스 연산을 하나의 **논리적인 작업 단위**로 묶어서 실행  
>   > a. 모든 연산 성공적 -> 트랜잭션 **커밋**, DB 반영  
>   > b. 하나라도 실패 -> **롤백**, 이전 상황 복원
